# Bundles

Pre-packaged ZIP archives for sharing with non-repo collaborators (Brenden, Chip, anyone else who shouldn't be navigating GitHub).

## How to use

Each bundle is a snapshot at a specific story-canon version. Pick the version that matches what you want to discuss.

| Bundle | Version | Contents |
|---|---|---|
| `nexgen-story-bundle-v0.3.1.zip` | Story canon v0.3.1 | The 9 story-related files: STORY-DIRECTION.html, MASTER-STORY-ELEMENTS.md, STORY-BIBLE.md, LINKEDIN-DRAFT-v0.3.md, nexgen-backstory.html, NexGen_Transformation_Journey.html, SELF-ASSESSMENT-SPEC.md, STRATEGIC-NOTES, BRENDEN-JOURNEY.md |

## How to read a bundle

After unzipping:
1. Open `STORY-DIRECTION.html` in any browser — that's the cinematic pitch piece
2. Open `MASTER-STORY-ELEMENTS.md` in Word, Notepad, or any text editor — the canonical story reference
3. Open `LINKEDIN-DRAFT-v0.3.md` — copy/paste-ready LinkedIn version
4. The remaining files are deeper-dive references

## When to ship a new bundle

- After any major story-canon version bump (v0.4, v0.5, etc.)
- After Brenden's voice memo lands and the placeholders get replaced with real numbers
- Before a major external send (EPLAN partnership pitch, advisor review, board update)

## Notes

- **Bundles are snapshots, not living docs.** If a recipient is going to keep collaborating, they should clone the repo or use the GitHub web UI. Bundles are for one-shot review or external sharing.
- **Bundles are committed to the repo.** This is intentional — version-stamped artifacts you can point at later. Yes, they're binary; the cost is tiny (sub-100KB) and the convenience of "just download this" is worth it.
- **Bundles are flat.** No folder structure inside. Each file lives at the root of the ZIP for ease of reading.
